# 集成与定位设计

## 宿主边界

Recall Desktop 是独立 SwiftUI/AppKit 应用及菜单栏面板，依赖用户触发的 macOS 辅助功能、宿主公开快捷键、`codex://threads/<UUID>` 对话链接和本地 App Server stdio。它不是嵌入消息菜单的插件，也不是浏览器扩展。

当前支持同一宿主桌面应用中的 Codex 和 ChatGPT Work。ChatGPT Work 的可用性已由项目作者在本机多次实测确认，见[验证记录](validation.md)。下文的 bundle ID、链接协议和组件名称用于说明宿主识别及读取机制，不代表只支持界面中的 Codex 模式；网页版、移动版与其他宿主不因此获得支持。

宿主 bundle ID 为 `com.openai.codex`。优先从唯一的运行宿主取得实际 bundleURL；无运行副本时使用 NSWorkspace 的应用登记位置。不依赖宿主文件名或 `/Applications` 目录，因此可发现改名或位于用户应用目录的安装。多个不同位置的运行副本、身份不符或当前副本缺少组件时明确停止，不混用其他副本。这里的身份检查是 bundle ID 检查，不构成开发者证书认证；请从可信官方来源安装宿主。

组件相对位置仍为 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`。组件布局变化时给出更新或重新安装宿主的提示，不自动下载或扫描其他文件。开发者仍可通过显式的 `RECALL_CODEX_PATH` 覆盖；无效覆盖不会静默回退。变量由启动进程继承，Finder 启动不保证继承终端变量。开发者可在终端设置变量后直接执行应用的 `Contents/MacOS/RecallDesktop`。

初始化能力含 `experimentalApi: true`。客户端允许的方法为 `initialize`、`thread/read`、`thread/items/list`；初始化后通知 `initialized`。目标对话的存储方式必须支持 item 分页；否则接口可能拒绝，当前实现明确停止，不迁移宿主历史。初始化中的客户端版本读取应用 Info.plist，未打包的测试进程使用 `development`。官方接口或结构变化时应明确失败，不退回登录态内部接口或私有数据库。

## 采集

验证当前前台宿主和指针命中归属；读取并核验完整正文边界；临时复制对话深链接，通过只读历史将完整原文/渲染正文对应到对话、轮次、消息身份。只有完整对应才打开备注表单。

先读取宿主应用的公开 `AXRole`，以促使 Chromium 初始化原生辅助功能，再读取窗口和命中位置；该兼容处理不保证每个宿主版本都会暴露正文。正文未就绪时，在原窗口、原指针坐标以 4 秒预算、最多 24 轮进行发现重试；系统辅助功能调用本身可能使实际耗时超过预算。正文已就绪时立即继续。期间切换应用、窗口或取消会停止。

候选发现合并公开的 `AXVisibleChildren`、`AXContents` 和 `AXChildren`，按节点身份去重并限制节点数、深度和时间。额外关系只用于发现指针下的只读文字，完整正文仍由原有完整树与来源历史核验。没有设置未公开的系统属性，也不修改宿主文件或启动参数。Chromium 的公开角色初始化行为可见[上游实现](https://chromium.googlesource.com/chromium/src/+/master/chrome/browser/chrome_browser_application_mac.mm)；实际宿主兼容性仍以验收为准。

## 返回

1. 按已存对话/轮次/消息身份预检目标仍存在、作者和原文未变。
2. 打开原对话并调用宿主查找；已知零个或多个结果会停止，计数不可读时仍需独立完整证明。
3. 关闭本次拥有的查找栏，通过控件树发现完整正文候选。短时限优先核验失败后，保留原扫描和屏幕采样后备。
4. 逐页重新读取全部最新来源历史，验证目标身份及定位片段、完整正文和工具/附件同文歧义。
5. 再次读取完整正文及最终可见坐标，检查前台、窗口、导航所有权和取消状态，才显示约 2.5 秒的非激活高亮层。

不存在消息级原生深链接；UI 对应仍受宿主查找和渲染约束。候选或缓存不能替代完整证明。错误、取消或无法唯一定位时明确停止。

正文比较和内容指纹会统一空白，原文还会与 Markdown 渲染结果对应，因此“全文核验”不表示逐字节相同。核验仍要求稳定的对话、轮次、消息身份及作者，并拒绝规范化后发生变化或不能唯一对应的正文。

## 存储和性能

JSON 原子保存及并发修订检查；内容变化且旧文件存在时备份，写入成功后尝试仅保留最近 20 份，删除失败可能多于 20 份；恢复先验证和确认，删除可短时撤销。备份读取/校验与确认后的恢复在后台执行，不设 64 MiB 文件门槛；恢复期间阻止界面写入和重新读取，继续使用相同存储修订。默认数据位置及权限、资源要求和剪贴板边界见 [PRIVACY.md](../PRIVACY.md)。

历史转换和匹配缓存有界、仅内存保存，键关联精确来源及查询，变化时重算。每次最终证明仍读取全部来源页。分块响应只扫描新增字节；界面候选按优先顺序核验，同轮减少重复控件读取。没有跨返回复用旧正文坐标来显示成功。

## 代码分工

| 文件 | 职责 |
| --- | --- |
| App.swift | 窗口、卡片、备注及备份交互、任务状态和快捷键 |
| Core.swift | 消息/标记模型、匹配规则、存储及数字诊断 |
| History.swift | 宿主实际位置发现、本地只读 RPC、历史分页与完整来源证明 |
| Native.swift | 辅助功能采集、宿主导航、完整正文位置和高亮 |
| Clipboard.swift | 仅内存的剪贴板暂存、取消收尾、版本保护和用户选择恢复 |
| AppIcon.swift | 旧系统运行中 Dock 图标随外观切换；新系统使用原生资源 |

使用 Apple 系统框架，不捆绑宿主 CLI、Swift 编译器或 Python。参考现有集成依据：[公开命令](https://learn.chatgpt.com/docs/reference/commands)、[App Server](https://learn.chatgpt.com/docs/app-server)。文档可变；不把某次接口可用等同于未来版本承诺。
